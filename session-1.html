Two files in. One page out.

HTML

The structure and the words. Headings, paragraphs, links, images, sections.

→
CSS

The appearance. Colour, size, spacing, layout, what happens on hover.

→
Browser

The house version: HTML is the walls, doors and rooms. CSS is the paint, the furniture and the lighting. The browser is the builder who reads both plans and puts the house up in front of you.

Section 2 · Prepare the workspace

A website is a folder.

your project folder
nova-tech-day/
├── index.html
└── styles.css
index.html
The home page. Browsers look for this name first, so a folder with an index.html “just opens”.
styles.css
All the appearance decisions, kept separately so one change can restyle the whole page.

Three naming rules that save an hour later:

  • No spaces. Use styles.css, never my styles.css.
  • Same capitals everywhere. Styles.css and styles.css are different files on many systems.
  • Say what it is. index.html, not page1final2REAL.html.

Route A · Recommended Everyone follows along

Set up in VS Code

  1. Make a folder on your desktop called nova-tech-day (or your own project name).
  2. Open VS Code → File → Open Folder → choose that folder.
  3. In the Explorer panel, click New File and type index.html.
  4. Click New File again and type styles.css.
  5. Save with Ctrl+S (Cmd+S on Mac). Do this constantly.
  6. Find index.html in your file manager and double-click it. It opens in your browser.
  7. Put VS Code on the left half of the screen and the browser on the right half.

The loop you will repeat all day:

Type → Ctrl+S → click the browser → F5 to refresh → look.

If nothing changes on screen, nine times out of ten you did not save, or you refreshed a different tab. Check those two before anything else.

Windows snap: Win+← and Win+→. macOS: drag windows to each half.

Section 3 · Your first HTML document New syntax

One element. Three parts.

index.html
<h1>Nova Student Tech Day</h1>

Opening tag

Starts the element and names its job. h1 means “the one main heading of this page”.

Content

The part a visitor actually reads. Change this and the page changes.

Closing tag

Same name with a / in front. It tells the browser where this element stops.

Opening tag + content + closing tag = one element.

Section 3 · One idea Nesting

Boxes inside boxes.

<html>
<head> — information about the page
<title> the tab name
<body> — everything a visitor sees
<h1> the main heading
<p> a paragraph

Nesting rule: whatever you open last, you close first. Like putting boxes inside boxes — you cannot close the outer box while the inner one is still sticking out.

correct
<p>Build <strong>something</strong> good.</p>
crossed over — do not do this
<p>Build <strong>something good.</p></strong>

Indentation — those two spaces at the start of a line — is only for humans. The browser ignores it. Your future self will not.

Instructor notes

Say
“Point at the dashed boxes. Each one is completely inside its parent. Never half in and half out.”
Expect
The crossed-over example looks fine to beginners because browsers often still render it. Say that plainly: “It usually works, and it will still eventually hurt you.”
Misconception
That indentation changes the page. It does not — it changes whether you can read your own file.
Hint first

Progressive build · Step 1 of 2 Type this

The four lines every page starts with

index.html
+<!doctype html>
+<html lang="en">
+  <head>
+    <meta charset="UTF-8">
+    <meta name="viewport" content="width=device-width, initial-scale=1.0">
+    <title>Nova Student Tech Day</title>
+  </head>
+  <body>
+  </body>
+</html>
<!doctype html>
“Use modern HTML rules.” One line, always first, never changes.
<html lang="en">
Wraps the whole document. lang tells browsers and screen readers the language.
<head>
Information about the page. Nothing here appears on screen.
<meta charset>
“Read this file as UTF-8”, so accents and symbols do not turn into rubbish.
<meta viewport>
“Do not pretend a phone is a desktop.” Without it, phones zoom out and everything is tiny.
<title>
The browser tab name. The one thing in head people actually see.
<body>
Everything a visitor sees goes here. It is empty for now.

Instructor notes

“Type it, do not paste it. Your fingers need to feel the angle brackets once.”

“VS Code closes tags for you. If it does, do not type the closing tag twice.”

Section 4 · Useful content New syntax

Attributes: extra facts inside the opening tag

index.html
<a href="#schedule">View the schedule</a>
href
Where a link goes. #schedule jumps to the element with id="schedule" on this page.
src
Which file an image should load.
alt
What the image shows, in words, for anyone who cannot see it.
id
A unique name for one element. Used once per page.
class
A label you can reuse on many elements. This is how CSS finds things.

The shape never changes: name="value", inside the opening tag, separated by spaces. Quotes around the value, always.

Missing quote = the browser swallows the next part of your line. If text vanishes, check your quotes first.

Instructor notes

Say
“A tag says what something is. An attribute says something extra about it. Name, equals, value in quotes.”
Expect
Confusion between id and class. One-line rule: “id = one specific thing, class = a group of things.”
Misconception
That attributes show on the page. Only alt ever becomes visible, and only when the image fails.
Hint first
“Where inside the tag do attributes live — before or after the element name?”
Timing
4 minutes.
Short session

Section 4 · One idea Choose correctly

It looks like a button. Should it be one?

Use a link <a> when…

  • It takes you somewhere — another page, or a section of this one.
  • “Register”, “View the schedule”, “Back to top”.
<a class="button" href="#register">Save your place</a>

Styled to look like a button. Still a link, so it still works with right-click, middle-click and back.

Use a button <button> when…

  • It does something on this page instead of going somewhere.
  • “Play”, “Add to list”, “Show more”.
<button type="button">Show more sessions</button>

Today's pages have no JavaScript, so nearly everything you build is a link.

Why bother? Both can be made to look identical. Only the correct one behaves correctly for keyboards, screen readers and the browser's back button. Choosing the right element is free accessibility.

Instructor notes

Say
“Ask one question: does it go somewhere, or does it do something?”
Expect
“But my link looks like a button, so it is a button.” Appearance is CSS; behaviour is the element.
Misconception
That button is the more “professional” choice. It is only right for actions.
Hint first
“If I middle-click it, should it open in a new tab? Then it is a link.”
Timing
3 minutes.
Short session

Solution
Goes somewhere → link. Does something → button.

Section 5 · One idea Six names

The map of almost every page you will ever build

<header> — the top strip: site name and
<nav> — the set of links to the main areas
<main> — the one-per-page container for the real content
<section> — one themed block: about, schedule, register
<article> — one self-contained thing: a card, a talk, a post
<footer> — the bottom strip: contact, credits, small print

Section or article? If you could lift it out and post it somewhere on its own and it would still make sense — that is an article. A speaker card is an article. “Our schedule” is a section.

One main per page. Everything that is not navigation, header or footer belongs inside it.

These elements do almost nothing visually. They are for meaning — and later, they make your CSS far easier to write.

That these elements change how things look. Show that they do not; only meaning changes.

Assignment 1 · Stretch Use at least one

Five new elements. Same rules as everything else.

try them here

The image will not load here — there is no team.jpg in this deck. Notice what the alt text does when a picture is missing.

ol
An ordered list. Use it when the order carries meaning: steps, rankings, a timetable. The numbers come free.
figure
figcaption
An image plus a caption, tied together so a browser knows the caption belongs to that picture. alt describes it; the caption comments on it.
blockquote
A quotation from somewhere else. Put a p inside it. Say who said it.
nested ul
A list inside a list item — not inside the ul. Look carefully at where the inner <ul> opens.
a link to a file
Write href="about.html" to reach another file rather than an id. No #. Same folder, exact spelling, exact capitals.

Use at least one of these, and be ready to say why that element and not a different one.

Assignment 1 · Before you hand it in Self-check

Ten checks, then submit.

Check it yourself first

  • Both pages open in a browser
  • Every nav link goes somewhere real
  • Page one links to page two, and back again
  • Every jump link lands on a section
  • The image loads — or you know why it does not
  • The alt text describes the picture
  • No link says “click here”
  • One h1 per page, no skipped levels
  • Every tag you opened, you closed
  • Nothing visible sits outside body

How it is marked — 20 points

  • Valid document structure, both pages4
  • Semantic regions used honestly4
  • Headings and nesting4
  • Links and images that work4
  • Real content, plus one stretch element4

No marks for looks. There is no CSS, so there is nothing to judge. Marks are for structure, working links and words worth reading.

The five most likely faults

  1. Link to page two spelled differently from the file — About.html is not about.html.
  2. Jump link with no matching id.
  3. Image path pointing somewhere that does not exist.
  4. A missing closing tag, so half the page goes strange.
  5. alt="" left on a photograph that actually matters.

Submit: put both files in one folder, zip the folder, upload it. Be ready to explain any line I point at.
