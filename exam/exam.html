Section B: Practical project 70 marks

A ticket page for a one-day event

Make up a one-day event: a tech meetup, a gaming tournament, a small concert, a football viewing party, a class reunion, anything you like. Then build a one-page website for it. The page tells people what the event is and when things happen, and it has a booking panel where they pick tickets, see the price add up, and book.

No real payments happen and nothing is saved. Everything runs on the page, in the browser, with your own HTML, CSS and JavaScript. You can build all of it in a phone editor such as Acode or Spck, or on a laptop with VS Code.

Your project folder

event/
  index.html
  styles.css
  script.js
  notes.txt
  images/

Part 1: HTML 14 marks

The page needs a correct skeleton: doctype, lang, charset, the viewport tag and a real title. Inside the body you need:

  • a <header> with the event's name and a <nav> whose links jump to at least three sections on the page. Every link must land on its section.
  • a <main> with at least four sections: About, Schedule, Tickets, and one more of your choice (FAQ, Speakers, Line-up or Venue).
  • a schedule written as an ordered list with at least four items, each with a time.
  • at least one image inside a <figure>, with real alt text and a <figcaption>.
  • a <footer> with your name and the event date.
  • exactly one <h1>, and no skipped heading levels.

The Tickets section holds the booking panel. It has three ticket types. Each one shows its name, its price, a minus button, the number chosen and a plus button. Under them goes the total, a name input, a phone number input with a label for each, a Book button, a Clear button and an empty paragraph for messages. Anything that does something on the same page is a <button>. Anything that goes somewhere is a link.

Part 2: CSS 18 marks

All styling goes in styles.css. Do not use style="" attributes. Pick a small set of colours and one or two fonts and stick to them. Text must be easy to read against its background.

  • Give the ticket types and other content blocks proper spacing with padding and margin, and set box-sizing: border-box on everything.
  • Use Flexbox in three places: the header, with the event name on one side and the nav on the other; the nav links, in a row; and the three ticket types, side by side.
  • Style each ticket type as a card with a border or background, and make the buttons look like buttons someone would want to press.
  • Buttons and links change in some visible way on hover, and show a clear outline when you reach them with the keyboard (:focus).
  • Use at least one technique from the CSS techniques session somewhere it makes sense: clamp() for the main heading, transform with transform-origin, a mask-image fade, a filter: blur() glow, or overflow: hidden to crop something on purpose.

Part 3: JavaScript 28 marks

Start script.js with your tickets stored as an array of three objects. Change the names and prices if they do not fit your event.

const tickets = [
  { name: "Regular", price: 3000, count: 0 },
  { name: "VIP", price: 10000, count: 0 },
  { name: "Student", price: 1500, count: 0 }
];

The total must always be worked out from this array. If you change a price here, the total on the page must change with it.

The plus button adds one ticket of that type, and the minus button takes one away. A count can never go below 0. The whole order can have at most 10 tickets. If someone presses plus when they already have 10, the count stays the same and the message paragraph says "You can book at most 10 tickets." The numbers on the page update every time.

Write a function that loops through the array and returns the total price of the order. Use it to update the total on the page after every change. The total can show as plain digits, so "16500" is fine.

When the order has 5 or more tickets, take 10% off. Show the price before the discount, the price after it, and the words "Group discount applied". For example, 2 Regular and 3 Student is 5 tickets: ₦10,500 before the discount and ₦9,450 after it.

When the Book button is clicked, read the name and phone number at that moment and check them in this order:

  1. If no tickets are chosen, show "Pick at least one ticket."
  2. If the name is shorter than 2 characters, show "Enter your name."
  3. If the phone number is not exactly 11 characters long, show "Enter an 11-digit phone number."

Show only the first problem found, and give the message paragraph the class error so it looks like a warning. If everything passes, remove that class, add the class success, and use a template literal to show a message like this:

Thanks, Ada. 5 tickets booked for ₦9450. We will text 08031234567.

The Clear button sets every count back to 0, empties both inputs and the message, and updates the page.

Finally, make one more part of the page respond to a click. For example, clicking an FAQ question shows or hides its answer, or clicking a speaker's name shows their short bio. Do it by adding and removing a class, and let your CSS do the hiding and showing.

Rules

You may use your class notes, the workshop slides and MDN. You may ask an AI tool to explain an error message, but not to write your code. Your instructor may ask you to explain any part of your project. Marks for a part you cannot explain can be taken away.

Before you submit

  • The page opens with no errors in the console.
  • Every nav link lands on its section.
  • You can add 10 tickets but not 11, and no count goes below 0.
  • With the starting prices, 2 Regular and 3 Student shows ₦10,500 before the discount and ₦9,450 after it.
  • Book with nothing chosen, with no name and with a short phone number, and you get the right message each time.
  • Clear puts everything back to the start.
  • notes.txt answers all three questions.
